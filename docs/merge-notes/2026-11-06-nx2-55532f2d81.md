## Resolution

- **Upstream's mechanism wins.** `BuiltinPatchRecord`, the apply loop and all of its validation
  (title/module/build gates, original bytes, executable padding, BSS timer state, every record
  validated before any is written, any user-mod byte taking precedence over the whole patch) are
  nx2's, unchanged. The apply log line is upstream's: `Applying built-in patch "<name>" (<n>
  records) to main`.
- **#216 is re-expressed as records.** Its four words (1.0f delta, `ldr s8`, `b` back, hook at
  `main+0x6E6CC4`) become four 4-byte records whose `original` is the word #216 checked (zero for
  the three cave words, the `fdiv` for the hook), `executable_padding` off: the same checks #216
  made, now transactional under upstream's loop. Same Add-Ons name, same bytes, same offsets
  (`nx2_oot_time.h`), so `nso.cpp`'s hook detection and the present-path delta write are untouched.
- **Table order:** Max Resolution, Real-time speed, Dynamic FPS by Dark.

## Default decision (fork-specific)

Both patches hook the same instruction (`main+0x6E6CC4`, the per-frame step `fdiv`); stacking two
speed corrections would double-correct. On this fork the exact measured-delta patch is preferred:

- `BuiltinPatch` gains one field, `yields_to`. Dark's record sets it to `"Real-time speed
  (built-in)"`. When that patch applied earlier in the same `PatchNSO` pass, Dark's is skipped with
  `Skipping "Dynamic FPS by Dark (built-in)": "Real-time speed (built-in)" applied and already
  corrects the frame step`.
- Dark's stays a listed Add-Ons entry (no config-schema change, so upstream's `[addon_config]`
  tests hold as written). Disabling "Real-time speed (built-in)" in Add-Ons lets Dark's apply with
  every upstream guard. Its checkbox reads enabled even while it yields; enabling both is
  unsupported, documented in `docs/nx2/ocarina-dynamic-fps.md` ("On this fork").
- Chosen over a default-off entry because Add-Ons only stores a disabled list: default-off would
  need an enabled-list or a config migration, a larger divergence from upstream.
