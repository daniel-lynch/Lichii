## Our switches on the merged tree

- **`EDEN_NX2_UNIFORM_BANK_REUPLOAD`** (`buffer_cache.h:1917`): still gates the whole 64 KiB bank
  re-upload block. #184's "native bank checks" only added a `contains()` pre-check inside the same
  condition (skip the GPU-modified lookup for a bank already re-uploaded this frame). Same
  behaviour, so `=0` still removes the re-upload.
- **`EDEN_NX2_GFX_STORAGE_SIZE_LIKE_COMPUTE`** (`buffer_cache.h:925`): untouched by #184. `=0`
  still sizes native graphics storage buffers by the word after the pointer.
- **Store-extent write mark / `native_compute_write_mark`:** untouched by #184. Its "write
  intersections" are texture-cache work, and "usage tracking" is the host `UsageTracker` run
  filling. Neither bounds a compute storage write mark, so nothing of ours is subsumed and it stays
  on its setting.

## Needs review

1. **Merge dev `9b2cc6519e` next.** Most important: `b1c4c69cb0` rewrites `UsageTracker`'s page
   mask, and #184 rewrote `Track` around `FillPages` in the same file. Its own test
   (`nx2_perf_draw_binds.cpp:165`) fails here, and the oracle it compares against has the
   shift-by-64 undefined behaviour that b1c4c69cb0 fixes (an empty tail range at a page-aligned
   end). Expect to update that test's `OldUsageTracker` to the 64-byte-unit mask when dev comes in.
2. **`GetFlushArea`, native titles (`buffer_cache.h:340-380`).** #184 stops Preflushable marking for
   Switch 2 titles. Our exact-preflush (80a4a84411) and flush-area narrowing (6269725930) remain
   but mostly sit idle for OoT. Watch for flicker, flashes or CPU-read stalls, and A/B with
   `EDEN_NX2_NATIVE_PREFLUSH=1`.
3. **`cpu_read_ranges` takes the read range, not the widened area.** In #184 the two are the same.
   Ours widens the area to the texture cache's range, and recording only what the CPU read keeps
   batch downloads off pages it never read.
4. **Two batched-download functions** (`DownloadMemoryRanges` ours, `DownloadRangesMemory` #184) do
   nearly the same thing. Ours handles mapped buffers without staging. Consider routing #184's
   call through ours.
5. **`ReadTrapTracker` (#184) vs our `ArmReadTraps`.** Ours is kept because it records a range only
   after the core armed all of it. #184's tracker records first. Its unit test still runs against
   the class, not the buffer cache.
6. **`vk_pipeline_cache.cpp:1495` mixed graphics pipelines.** Cached stages are built on the GPU
   thread and deferred stages on the worker. Translation-cache variants are inserted from the
   worker. Checked statically; exercised only by the harness run below.
7. **`maxwell_3d.cpp` `FrontDmaRead`:** our memory-writer wait replaces #184's full drain (as
   before #184). #184 counts it with `CountDmaRead` either way.
8. **`ConfigureDelta`:** the deferred fragment barrier now stays pending across delta draws, as on
   #184's main path. Fast-draw is opt-in and not exercised by the harness.
9. **CI:** `.github/workflows/build-check.yml` is in the tree. The fork rejects the push until the
   token has the workflow scope.
