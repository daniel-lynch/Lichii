## Why a plain `git merge origin/nx2` conflicted in 28 files

dev carries #184 and #193 as `a3e389b672` and `0053c49b4f`: re-created commits whose trees are
identical to nx2's `5f6066b26b` and `5a50f50e0b` (`git diff` between each pair is empty), made so
the fork could take them without `.github/workflows`. Git does not know they are the same, so its
merge base for dev and nx2 is still `27226d2568`, and a plain merge replays all of #184 against our
already-reconciled #184: 28 conflicted files, most of them (`nx2_debug_tools.cpp`, `maxwell_3d.*`,
`vk_frame_dump.*`, `debug_mcp.py` …) untouched by #194.

The merge was therefore done against the true base: #194's own diff (`5a50f50e0b..b06d1818ee`,
38 files) applied to dev as a three-way merge with `5a50f50e0b` as the base, and the result
recorded as a merge commit with nx2 `b06d1818ee` as its second parent. From now on `b06d1818ee` is
an ancestor of this branch, so the next nx2 merge has the right base and only sees upstream's new
work.

Result: **9 conflicted files, 14 hunks.** The other 29 #194 files merged without a conflict.

## Other changes in the merge

- **`DownloadMemoryRanges` (ours) removed.** It was the only caller-less copy left once
  `Nx2FlushListPages` took #194's form: #194's `DownloadRangesMemory` is now the same function
  (mapped buffers read in place, staged ones copied), plus the host-read barrier. This closes
  needs-review item 4 of the 5a50f50e0b note. Difference: a mapped-only batch now does a full
  `FinishForHostRead()` instead of waiting for the newest buffer's tick.
- **Upstream defaults that change dev's behaviour, taken without a conflict** (A/B switches already
  exist upstream):
  - `FlushWork`: the native submission budget on desktop goes from 4096 draws back to
    `SubmissionPolicy::DefaultNativeBudget` (128). `EDEN_NX2_FLUSH_DRAWS=4096` restores the old one.
  - `Scheduler::DeferFlush`: fence submissions batch within 500 µs instead of 5000 µs.
    `EDEN_NX2_FENCE_FLUSH_US=5000` restores it. `FenceManager::SubmitDeferredWork` (split back thread only) submits the
    deferred flush after signalling a delayed fence and before waiting on one.
  - `BindHostGraphicsUniformBuffer`: the 64 KiB native bank re-upload now uploads directly instead of
    marking the region CPU-modified. Still inside our `EDEN_NX2_UNIFORM_BANK_REUPLOAD` gate, so `=0`
    still removes it.
- **New upstream files taken as is:** `vk_pipeline_cache_prebuild.h`, FSR3 frame-gen fixes (frame
  generation stays off by default), `tools/nx2/*` host-visibility and FSR3 probes, and the tests
  `buffer_cache_ports`, `command_writer`, `split_fence_wait`, `pipeline_cache_files` additions,
  `maxwell_fast_method` and `pipeline_build` additions.
